# 单气缸验证操作手册 —— 下压气缸 G1 跑一遍自动流程

目标：用物理按钮模拟传感器，让 G1 下压气缸走完一整个自动循环。
前提：`xSimulation = TRUE`（全仿真），你在 I/O 映射页已绑定 `GVL_IO_Physical` 的 12 个点。

---

## 一、先理解：这次到底在测什么

自动流程是**串行**的，`E_AutoStep` 顺序固定：

```
10 FeedWait → 20 StopFeed → 30 Push(G3) → 40 Clearance(G4/G3/G2) → 50 Rotate(D8)
→ 60 PressDown(G1) → 70 KnifeDown(G9) → 80 SpindleOn(D3)
→ 90 Cutting(D2) → 100 StopCut → 110 PostCut → 120 Complete
```

**G1 下压在 60 步**，前面 5 个步骤必须先全部通过。所以这一轮实际验证的是整条链，
而不是单独一个气缸。这也是好事——能一次性暴露前面几台设备的接口问题。

### 关键区分：谁是真实、谁是仿真

| 设备 | 索引 | 本轮状态 | 靠什么到位 |
|---|---|---|---|
| G1 下压 | 9 | **真实** | 你的按钮 → `xDiG1Extend` |
| G2 侧挡 | 10 | **真实**（若也置 TRUE） | 按钮 → `xDiG2*` |
| G3 侧推 | 11 | **真实**（若也置 TRUE） | 按钮 → `xDiG3*` |
| G9 盘刀升降 | 17 | **真实**（若也置 TRUE） | 按钮 → `xDiG9*` |
| D1 皮带 / D2 走刀 / D3 盘刀 / D4 定长 / D5 升降 / D7 机械手 / D8 旋转 | 1,2,3,4,5,7,8 | **仿真** | 内部 500ms 定时器自动完成 |
| G4 流利条 / G7 升降 / G8 夹爪 | 12,15,16 | **仿真** | 内部 500ms 定时器自动完成 |

**建议第一轮只把 G1（索引 9）置 TRUE**，其余气缸保持 FALSE 走仿真。
这样能以最小变量先把链路跑通，确认没问题再逐个加。

---

## 二、准备：三处置位

### 1. 仿真开关保持 TRUE

`GVL_Parameters.xSimulation := TRUE`

> 注意：这个开关同时决定**面板按钮从哪读**。TRUE 时面板信号来自
> `GVL_Simulation.stPanelInputs`，**不是物理按钮**。所以下面的模式/启动按钮
> 要在监视表里改，不是按外面板。

### 2. 接管 G1

`GVL_RealDevice.stSettings.axRealDevice[9] := TRUE`

其余 `axRealDevice[1..17]` 全部保持 FALSE。

### 3. 确认安全许可

`GVL_Simulation.stSettings.xSafetyOK := TRUE`（默认就是 TRUE）

---

## 三、跑流程：分两段

### 第 1 段：初始化（必须先做）

自动流程要求整机处于 `Ready`，而 `Ready` 只能在初始化完成后得到。

在监视表按顺序操作 `GVL_Simulation.stPanelInputs`：

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | `xAutoMode := TRUE` | 模式转自动 |
| 2 | `xInitialize := TRUE` → 保持约 2 秒 → `FALSE` | 整机进 `Initializing` |
| 3 | 观察 `GVL_Interface.stStatus.eState` | 变成 `Ready` 即成功 |
| 4 | 观察 `uiInitializeStep` | 走 10→20→25→30→40→1000 |

**这一步会自动抬起 G1**（初始化第 10 步要求 G1 到 0.0 抬起位）。

> ⚠️ **这里就会第一次考验你的按钮**：初始化要 `F_Done(aStatus[9], udiToken)`，
> 即 G1 必须报"已到手 0.0"。而 G1 姿态来自 `xDiG1Retract`。
> **所以初始化前，`xDiG1Retract` 必须是 TRUE**（模拟"气缸已抬起"）。
>
> 如果初始化卡在 `uiStep = 10` 不动，30 秒后报 `4610`，就是这里没过。

### 第 2 段：启动自动

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 确认 `eState = Ready` | |
| 2 | `xStart := TRUE` → 保持约 1 秒 → `FALSE` | 整机进 `Automatic` |
| 3 | 观察 `GVL_Interface.stStatus.eAutoStep` | 开始按 10→20→30… 推进 |

---

## 四、逐步要按哪些按钮

按 `eAutoStep` 的实际值配合操作。**同一时刻只需关心当前步**：

| eAutoStep | 步骤名 | 你要做的 |
|---|---|---|
| 10 | FeedWait | 等仿真来料。D1 皮带转起来后约 1 秒，`xMaterialAtLength` 自动变 TRUE |
| 20 | StopFeed | 不用操作，D1 停转即过 |
| 30 | Push | G3 侧推。若 G3 是仿真→自动过；若置了 TRUE→**按 `xDiG3Extend`** |
| 40 | Clearance | 仿真全自动（G4降/G3松/G2降）。若 G2 置 TRUE→**按 `xDiG2Extend`** |
| 50 | Rotate | D8 仿真旋转，自动过 |
| **60** | **PressDown** | **G1 下压：按 `xDiG1Extend`，同时松开 `xDiG1Retract`** |
| 70 | KnifeDown | G9 下降。仿真自动过；置 TRUE→**按 `xDiG9Extend`** |
| 80 | SpindleOn | D3 仿真运行，自动过 |
| 90 | Cutting | D2 仿真走刀，自动过 |
| 100 | StopCut | 自动过 |
| 110 | PostCut | 抬刀抬压。**G1 要松开 `xDiG1Extend`、按 `xDiG1Retract`** |
| 120 | Complete | 完成，回 `Ready` |

### 第 60 步的重点

这是你要验的那一步。两个动作必须**同时**发生：

```
xDiG1Retract := FALSE    ← 松开"抬起"按钮
xDiG1Extend  := TRUE     ← 按下"下压"按钮
```

**只按 extend 不松 retract 会报 3003**（两端同时有信号 → 姿态不可信 → 整机 Fault）。
这是气缸测试最常见的错误。

同理，第 110 步 PostCut 抬刀时，要反过来：
```
xDiG1Extend  := FALSE
xDiG1Retract := TRUE
```

## 五、在线要盯的变量

按这个顺序看，能最快定位问题：

| 变量 | 正常表现 | 异常含义 |
|---|---|---|
| `GVL_Interface.stStatus.eState` | Ready → Automatic → Ready | Fault = 出故障 |
| `GVL_Interface.stStatus.eAutoStep` | 按 10/20/30… 递增 | 卡住不动 = 当前步设备没到位 |
| `GVL_Interface.stStatus.udiAlarm` | 0 | 非 0 看数值定位 |
| `GVL_Interface.stStatus.uiBlockedDevice` | 0 | 非 0 = 该设备被互锁挡住 |
| `GVL_Interface.aDeviceStatus[9].lrPosition` | 随按钮在 0.0/1.0 跳 | 不动 = 传感器没读到 |
| `GVL_Interface.aDeviceStatus[9].xError` | FALSE | TRUE 看 `udiErrorID` |
| `GVL_IO_Physical.xDoG1Valve` | 下压期间 TRUE | 一直 FALSE = 命令没下来 |

## 六、错误码对照

| 码 | 含义 | 处理 |
|---|---|---|
| `3003` | 气缸两端同时有信号 | 松开一个按钮 |
| `3004` | 3 秒内两端都无信号 | 按下代表当前位置的那个按钮 |
| `3005` | 命令发出 10 秒未到位 | 检查按钮是否按了、映射是否绑对 |
| `10009` | 整机级：设备 9 故障 | 对应上面 300x，先修设备 |
| `4610` | 初始化卡在第 10 步 | G1 未到抬起位 |
| `4660` | 自动卡在第 60 步 | G1 未到下压位 |
| `4800` | 非法主步骤 | 通常伴随其它错误 |

## 七、常见坑

**1. 只改了 `axRealDevice[9]`，但 `xSimulation` 仍 TRUE**
这是对的。`xSimulation` 管"面板和未接管设备走不走仿真"，`axRealDevice[9]` 管
"这一台走真实"。两者可以并存，这就是"混跑"。

**2. 初始化的 G1 要求是 0.0（抬起），不是 1.0**
所以进初始化前必须先让 `xDiG1Retract = TRUE`。

**3. 互锁会挡住 G1 下压**
`FB_Interlocks` 对 9 号有要求：目标 >0.5 时，必须
`D8 不忙 AND G9 抬起 AND D2 在 lrCutHome`。
仿真设备这些条件自动满足；但如果你把 D2 或 D8 也置了真实却没回零，
会被挡，表现为 `uiBlockedDevice = 9`。

**4. 松开按钮的时机**
单电控阀靠**持续通电**保持位置。`FB_RealCylinder` 会一直输出阀电平直到
收到新的 Position 或 Stop。所以按下 extend 后，**按钮可以松**——
气缸保持在下压位，靠 `xDiG1Extend` 的传感器反馈维持姿态。

## 八、验证顺序建议

第一轮跑通后，按这个顺序逐个加真实设备，每次只改一台：

1. 只 G1（索引 9）—— 本次目标
2. 加 G3（11）—— 第 30 步考验
3. 加 G2（10）—— 第 40 步 Clearance 考验
4. 加 G9（17）—— 第 70 步 + 互锁最复杂的一台

每加一台之前，先确认上一轮能完整跑完 `10 → 120`。
